接口配置生成使用说明

本包 Java 17 / Spring Boot 3.5.16。生成器运行无需数据库或 Maven；生成业务工程的构建、测试需要匹配的 JDK、Maven 和完整业务依赖仓库。

1. 新增能力

  • 三套默认接口规范：LEGACY、REST、BANK_POST。
  • 每个已启用 CRUD 接口可指定 HTTP 方法、相对路径、业务字段位置、ID 位置。
  • CREATE、UPDATE、PAGE 可分别配置接收字段白名单、必填字段。
  • bodyProperty 生成一层嵌套请求封装 DTO，执行 @NotNull 与 @Valid 级联校验。
  • FULL 与 PARTIAL 更新。部分更新识别未传、显式 null 与具体值，动态 SQL 只更新已传字段。
  • IN 多值查询，最多100项；拒绝空列表、null 元素和超长/超精度元素。
  • 同步生成 openapi.json、interface-config.json、frontend/api.js、requests.http 以及适配当前配置的测试。
  • GET 查询使用正式字段白名单，拒绝未知参数及内部 offset/LIKE/范围校验属性。
  • JSON 的 ID/整数字段拒绝小数，避免默认截断造成错误记录操作。

2. 替换与启动

停止旧助手，备份 JAR、data 和外置模板。Windows 使用 start-windows.cmd，Linux 使用 bash start.sh。默认访问 http://127.0.0.1:8790；/api/config 显示本包的实际工具和模板版本。外置模板会覆盖内置模板，升级时须同步适配。本次升级不会直接改写业务源码。

3. 页面操作

  1. 在“需求与代码生成”载入合同示例或导入原规格。
  2. 在“接口定义”选择默认规范和修改语义。
  3. 展开对应操作，设置方法、相对路径、ID位置与业务字段位置。留默认项即可继承预设；路径输入空字符串表示接口前缀本身。
  4. 点击“指定接收字段”选择白名单；点击“指定必填字段”设定该接口额外的必填约束。
  5. 如需 JSON 封装，填写 data、filter、changes 等属性名称。
  6. 查询方式选择“多值列表”可生成 IN 查询。
  7. 点击“生成并预览代码”，下载 bundle.zip；查看 Controller、DTO、Mapper 及 openapi.json。
  8. 按生成包 README 编译测试，再在真实开发库联调。

“载入接口配置示例”展示全 POST、PARTIAL、嵌套封装和列表查询。完整包 examples 目录提供 REST、全 POST、部分更新和自定义参数位置的规格。Excel/Word 仍用于基础字段导入，接口扩展配置通过页面或 JSON 设置。

4. 预设默认值

操作 LEGACY REST BANK_POST
CREATE POST 前缀，JSON POST 前缀，JSON POST /create，JSON
UPDATE FULL PUT /{id}，路径ID＋JSON PUT /{id}，路径ID＋JSON POST /update，JSON中含ID
UPDATE PARTIAL PATCH /{id}，路径ID＋JSON PATCH /{id}，路径ID＋JSON POST /update，JSON中含ID
DETAIL GET /{id} GET /{id} POST /detail，JSON中含ID
PAGE POST /page，JSON GET 前缀，URL查询参数 POST /page，JSON
DELETE DELETE /{id} DELETE /{id} POST /delete，JSON中含ID

以上为相对 basePath 的路径，不是完整地址。例如 basePath=/contracts，/update 表示 /contracts/update。

5. JSON 配置格式

在原 generation-spec.json 顶层增加：

{
  "apiProfile": "BANK_POST",
  "updateMode": "PARTIAL",
  "endpoints": {
    "CREATE": {"path": "/add", "bodyProperty": "data"},
    "UPDATE": {"path": "/edit", "fields": ["amount", "signDate"], "bodyProperty": "changes"},
    "PAGE": {"path": "/search", "fields": ["contractNo", "signDate"], "bodyProperty": "filter"}
  }
}

这是新增配置片段，必须与包名、实体名、表名、operations、fields 等原规格一起提交，不是完整规格。完整示例见 interface-config-spec.json。

配置项 含义
apiProfile LEGACY/REST/BANK_POST；缺省 LEGACY
updateMode FULL/PARTIAL；缺省 FULL；PARTIAL 要启用 UPDATE
endpoints 键是已启用的 CREATE/UPDATE/DETAIL/PAGE/DELETE
method 覆盖 HTTP 方法，使用大写
path 相对路径；可为空或静态路径；动态参数只支持 {id}
requestIn 业务 DTO 的 BODY/QUERY；QUERY 仅支持 PAGE
idIn UPDATE/DETAIL/DELETE 的 PATH/QUERY/BODY；参数名固定 id
fields 业务字段根名称白名单；null/缺省继承默认；空数组表示没有业务字段
requiredFields 选中字段中必须出现的字段；null/缺省继承默认
bodyProperty 单层嵌套封装属性；只用于 BODY DTO；空/缺省为直接 DTO

范围字段在 fields/requiredFields 中填写根名 signDate，实际生成 signDateFrom/signDateTo。范围根名标为必填时起止均必填。

约束：CREATE 仅 POST JSON；UPDATE FULL 支持 PUT/POST，PARTIAL 支持 PATCH/POST，均 JSON；查询支持 GET/POST；删除支持 DELETE/POST；GET 不接收请求体，DELETE 不接收 JSON ID。ID 改为 QUERY/BODY 时必须同步把路径中的 {id} 去掉。方法、路径发生冲突或配置未知字段时拒绝生成。

CREATE 不能遗漏数据库 required=true 的字段，也不能放宽其必填约束。UPDATE 只能选择 editable=true 字段。PARTIAL 不允许 requiredFields 非空；字段是否可清空由原字段 required 决定。

6. 实际传输示例

新增：POST /contracts/add

{"data":{"contractNo":"HT2026-001","amount":100.00,"signDate":"2026-10-10"}}

部分更新：POST /contracts/edit

{"id":1,"changes":{"amount":120.00}}

未传 signDate 保持原值；若 changes 中显式 signDate:null，且该列允许为空，则清空。amount 为非空列，amount:null 会返回400。只有 id 或空 changes 会返回400。

列表查询（将 contractNo 的 query 改为 IN）：POST /contracts/search

{"filter":{"page":1,"size":20,"contractNo":["HT2026-001","HT2026-002"]}}

GET 查询使用重复参数：

GET /contracts?page=1&size=20&contractNo=HT2026-001&contractNo=HT2026-002

null 列表不限制；JSON 空列表拒绝，而不是放大成无条件查询。GET 无法区分未传列表与被客户端省略的空列表，生成的 Axios 序列化器会先拒绝空列表和空元素。日期条件使用 ISO 日期/本地日期时间。LocalDateTime 不带时区，生成文档使用自定义 local-date-time 格式；涉及跨时区系统需另行确定协议。

frontend/api.js 接收行内已有 Axios 实例，例如 createContractApi(request)。调用 update(id, {amount:120}) 时包装和 ID 位置由生成代码处理。权限、Token、错误提示、金额与长整数的前端精度处理继续复用行内规范。

7. 验证边界

生成时验证规格与 Java/XML 语法，不自动编译，不连接业务库。生成结果 compilation=NOT_RUN；下载后执行 mvn verify 或配置完整依赖仓库运行 build-offline.sh/cmd。

实际验证结果见对应发行包 verification-summary.json。H2、静态契约与示例宿主测试各有覆盖范围，不能代替真实 MySQL、麒麟、行内网关和业务验收。

requests.http 的空对象是待填写的请求草稿，必填未填写时预期400。openapi.json 来源于相同接口配置；范围起止等跨字段约束需要运行测试确认。认证和权限尚未生成，不能根据请求样例通过判断生产就绪。

8. 支持范围与旧问题

本版仍是单表 CRUD 生成器。嵌套能力指一层请求 DTO 封装，列表能力指 IN 查询；任意对象树、合同与明细的多表写入、批量写入、审批状态机、文件上传、Header映射与认证适配需要明确业务映射后开发，不生成空业务成功接口。

先前审查指出的助手其他模块问题（例如部分契约比较/校验、回归报告脱敏问题）不属于本次接口生成升级，不能据此认为已全部修复。框架基线仍按原交付保留，本次不宣称完成依赖漏洞扫描或生产上线认证。
