生成代码质量与验收说明

本包 Java 8 / Spring Boot 2.7.18，与另一 Java 平台同步维护。检查生成代码应同时保留规格、generation-manifest.json、生成工程测试结果和目标环境证据。

生成结果的含义

语法规整与 Java AST 校验只证明可解析；compilation=NOT_RUN 表示生成请求没有自动执行业务工程的编译。下载工程后按 README 执行 Maven verify。运行包不含 Maven 或完整业务依赖仓库，源码包依赖只保证生成器自身离线构建。

输入与接口边界

生成代码包括 DTO 校验、严格 JSON 输入、查询字段白名单、ID 校验、金额精度和日期范围约束；Service 的校验依赖 Spring 代理。PARTIAL 更新区分未传、显式 null 和具体值；FULL 的缺省字段行为需与调用方确认。CONTAINS 将百分号、下划线及转义符按字面匹配。

异常与事务

独立工程由全局异常处理器返回一致的状态和错误信息，未预期错误提供错误编号。写方法通过 Spring 事务代理执行，异常向外传播才会触发回滚。宿主模式复用宿主协议，需确认异常类型、HTTP 状态、成功码和字段映射。异步、定时及消息消费另行配置异常策略。

生产选项及验收

按规格生成乐观锁、幂等、权限扩展点、审计、Outbox、请求关联和生产接入说明。配置扩展点不表示真实身份、数据权限或外部可靠投递已经实现。MySQL 只读验收与明确启用的 CRUD 验收使用不同确认入口，先核对生成 README 和专用目标环境，不在生产库运行测试清理。

文档与版本比较

从生成契约保存或扫描业务源码，下载 OpenAPI、HTML 与 Markdown。响应头必填和 required 原始字段可见；未知、递归及复杂组合约束保留覆盖缺口。变更检查按请求／响应方向识别类型、必填、额外属性、精度、媒体类型和服务地址变化，结构兼容不等于业务语义验收。

重新生成与历史管理

保留旧规格及清单，在“代码更新与冲突”提交新规格与当前代码 ZIP，先审阅差异和冲突，再合并到业务分支。工具生成结果、候选合并结果与正式上线代码应各自标记来源，历史快照不可替代目标工程的编译及业务测试。

证据与持续维护

对应发行包的 verification-summary.json 记录实际执行范围，不应沿用历史版本的测试数量。SBOM 提供组件清单，仍需按组织批准基线完成漏洞、许可证和支持策略检查。麒麟实机、真实 MySQL、并发、容量、回滚恢复与行内公共组件应在目标环境验收。
