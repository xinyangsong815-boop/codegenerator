业务场景回归使用说明

本功能向配置的业务服务发送真实 HTTP 请求。先保存环境和场景，确认目标为专用测试环境，再执行。完整启动方法和默认地址见使用说明。

1. 配置目标环境

默认允许 http://127.0.0.1:8080。其他地址在助手启动时通过 tool.regression.allowed-targets 明确配置。例如 Linux 在运行包根目录执行：

bash start.sh --tool.regression.allowed-targets=http://127.0.0.1:8080,http://10.0.0.5:8080 --tool.data-dir=./data

Windows 可向 start-windows.cmd 传递同样参数。baseUrl 只填写协议、主机、端口；pathPrefix 只限制可请求范围，不自动添加到步骤路径。例如允许 /api 后，步骤仍需写 /api/contracts/{id}。

2. 编辑并保存场景

  1. 载入空白场景，或 合同 v2 示例。
  2. 按真实接口更换方法、路径、字段、状态码及响应指针。字符串 ID、原生数字 ID 必须与契约一致。
  3. 按新增、查询、修改、再次查询的顺序填写步骤，确认业务断言；只验证 HTTP200 不能证明业务正确。
  4. 保存步骤和场景，校验结构后执行。未保存的内容不会代替已保存场景参与运行。

3. 变量和断言

用 {"$var":"id"} 引用前面已经定义或提取的变量，不能在字符串中写 ${id}。JSON Pointer /data 读取 data 本身；/data/id 读取其中 id。query 中基本值数组使用同名参数重复传输，暂不支持嵌套对象或空数组。断言预期应反映业务结果及权限约束。

notExists 检查字段不存在；exists、notExists、notNull 可省略 expected，或填写布尔值。字符串与数字不相等；对象／数组内数值按数值一致性比较。版本影响报告只关联已声明接口、字段及断言，不能验证未建模的业务含义。

4. 凭据和报告

Token、Session Cookie、CSRF 在执行区临时填写，不写入持久场景或业务变量。报告不保存完整请求／响应正文；资源指针只提取所需的标识值，不应选取包含客户信息或密码的完整对象。运行报告、日志和存储目录仍需项目权限与留存管理。

5. 失败、取消与数据清理

断言失败与清理状态分别保留，整体结果同时考虑执行、覆盖和清理。取消不能撤销已提交的请求。MANUAL_REQUIRED 表示需要人工清理，确认重置只记录确认，不会重置数据库，也不会抹去失败的清理断言。

回归引擎不是压测器；事务竞争、超时恢复、重复提交、真实数据库驱动、网关和目标操作系统仍需专项验收。重启后发现损坏历史记录会保留恢复线索，应先备份再处理，不能通过删除错误记录掩盖失败。

6. 运行与离线构建

运行包无需 Maven、Node、Python 或外网，但必须使用与平台匹配的 Java。源码包用自带构建脚本和校验后的生成器依赖构建；生成业务工程需要独立 JDK、Maven 和完整业务依赖仓库。工具默认 http://127.0.0.1:8790，生成业务工程默认 http://127.0.0.1:8080。

7. 编辑期间的等待与确认

导入、打开、生成草稿或重排步骤期间继续编辑时，工具会保留后续内容并提示重新操作。运行前校验期间若切换了场景或目标环境，本次不会继续发起运行；请保存并重新确认。临时凭据在运行提交或校验失败后清除，再次执行需要重新填写。人工重置的响应只更新对应的运行记录。
