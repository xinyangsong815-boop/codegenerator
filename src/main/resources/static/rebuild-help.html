离线开发助手 2.1.1-rebuild.8-java8

本包目标 麒麟 Linux / Java 8 / Spring Boot 2.7.18。Java8 与 Java17 同步维护、分别构建测试。基线来自用户认可的本机恢复源码；原 2.2.1 源码未取回，不包含其完整 Apifox 工作台或集合数据驱动。

开始使用

  1. 准备 Java 8。运行包执行对应 start 脚本，访问 http://127.0.0.1:8790。源码包先用完整 JDK 执行 build.ps1 或 bash build.sh。
  2. 在“需求与代码生成”核对规格、字段、接口和生产选项，再生成预览。字段简表可展开全部高级列。
  3. 在生成结果查看“生产接入手册”和“生产缺口”，下载工程，在项目执行 Maven verify。H2 测试和本地编译不能替代真实项目验收。
  4. 保存生成契约，再检查文档、版本变化、Mock 和真实业务回归。旧项目通过三方合并保留人工修改。

本轮升级：文档与测试准确性

  • 源码文档保留整数、数字和布尔默认值类型；解析类级响应状态及方法覆盖，未知状态保留 default 占位并要求复核。Controller 继承映射尚未解析时明确列入覆盖缺口。
  • 接口版本提供可离线阅读的 HTML 和 Markdown，包含参数、请求、响应、响应头、示例与覆盖缺口。旧版本记录也可使用新的阅读入口。生成工程同时附带两种接口说明。
  • 生成 Controller 提前限定 application/json，不接受此格式的请求在业务调用前返回无正文的 406；增加对应集成测试。宿主模块的错误协议仍需宿主对齐。
  • 回归声明的资源标识缺失或类型不符会失败；请求头变量必须为字符串，动态存在性断言只接受布尔预期。字符串 size 按 Unicode 字符数计算。
  • 清理步骤在中断恢复时同步标记；JUnit 名称包含步骤标识，避免同名步骤覆盖。文档与规格 JSON 拒绝重复键及尾随内容。版本比较新增响应头删除提示，并优先显示实际不兼容结论。

保留的前版修复

  • 版本比较识别 anyOf 必填组合的收窄／扩展，按请求和响应方向判定；警告不再显示为无条件 PASS。
  • 接口索引包含路径级参数及操作覆盖；示例中的普通 $ref 和业务字段名不会误作 Schema 约束。
  • 嵌套对象、数组的数字断言按数值一致性比较；JSON 无效时不能让可选变量提取悄悄通过；清理步骤纳入版本影响检查。
  • 业务断言与整体结论分别显示。整体结论包含执行和清理状态；人工确认数据已清理不会抹去失败的清理断言。HTML、JSON 和 JUnit 保留实际失败。
  • 并发生成隔离模板来源记录，保留前版的草稿、迟到响应保护和断线恢复。

新增生产接入支持

  • 独立工程生成同步请求 X-Request-Id、受限编号校验、脱敏方法／状态／耗时日志与 MDC 恢复；内部错误编号与响应头一致。
  • 生产配置启用优雅停机、必要的连接参数与敏感日志约束，提供环境预检脚本和 production-runbook.md。
  • 生成 MysqlAcceptanceTest，默认跳过。仅在明确启用、配置并确认专用目标库后执行只读连接与表列检查；不会执行初始化 SQL。
  • 生产缺口继续列出真实认证、对象／机构权限、业务规则、持久化幂等、审计、迁移、监控、依赖安全及恢复要求。结构配置不会自动变成验收通过。

版本与回归结论

FAIL 表示发现不兼容或执行失败；INCOMPLETE 表示覆盖或清理未完成；REVIEW_REQUIRED 表示需要复核；PASS 仅对应声明范围。取消不会撤销已提交操作，确认清理只记录确认，不替你修改数据库。

断言与文档边界

notExists 检查字段不存在；exists、notExists、notNull 可省略 expected，或填写布尔值。对象和数组内的 JSON 数字按数值比较；字符串 "1" 与数字 1 不相等。仅支持已声明的 OpenAPI 3.0.0～3.0.3 子集，未支持语义保留覆盖缺口。金额和大整数建议 STRING_NUMBERS，浏览器原生 JSON 数字仍有 JavaScript 精度边界。

本轮本机验证环境为 Windows、对应真实 JDK 与 H2；麒麟实机、真实 MySQL、行内平台、性能、支持策略和恢复验收仍需在目标环境完成。原 Apifox、文件上传、集合数据驱动与 Token 提取功能不在当前恢复版范围。

本轮新增：代码版本库、注释与可靠消息支持

  • “代码版本库”可保存当前生成结果、文本文件集合或UTF8源码ZIP；默认保留ZIP路径，仅显式勾选时移除唯一包装目录。仅包含src目录的导出包再导入不会丢路径。
  • 创建项目与分支，填写提交说明，保存完整快照。未包含的旧文件视为删除。提交携带当前分支头，遇到并发修改先刷新再核对，不会静默覆盖。
  • 可比较同一项目的两个提交（包括跨分支）、查看文件、下载ZIP；恢复建立新提交，不覆盖原历史或本地磁盘目录。备份整个data/code-repositories。它是本机轻量文本快照库，不支持Git remote/push/pull、多人认证或自动合并。
  • ZIP拒绝.git、常见凭据及二进制；单文件5MiB、合计20MiB、最多1000文件。配置模板也需自行确认没有真实密码；不要上传运行数据、依赖或构建目录。
  • 生成注释改为实际函数与组件说明；错误数据源事务不能写审计。hooks启用时提供显式Outbox投递器，由宿主调度，支持租约、恢复、退避和死信，提供至少一次投递，接收端必须按eventId去重。不会启动即自动发送。
  • 旧v17模板的Outbox表需要先核对并迁移lease_token、leased_until、delivered_at三列；新版再生成候选会提示模板级辅助表迁移。不能只因业务字段不变就跳过数据库评审。
  • 契约比较与文档修复响应required、响应头必填、HTTP头大小写、媒体类型及无效响应声明；缺少必需信息会明确不完整，不将静态结果当运行验收。

rebuild.8：草稿与异步操作修复

  • 代码版本库切换项目或分支后立即清除旧头与历史；查看提交、文件时只接收当前选择的响应。加载更早历史时发现分支头变化会重新载入首页，避免重叠或漏项。
  • 恢复快照、创建分支、上传源码和打开场景期间的新编辑会保留。写入失败或并发冲突仍保留草稿；操作结束后再核对当前内容提交。
  • 回归执行在定义校验后重新核对已确认的场景与环境，期间改变目标会停止提交并要求重新确认。验证失败也清除临时凭据。场景导入、草稿生成、重排步骤和读取示例不会覆盖等待期间的新编辑。
  • 版本影响报告与Mock试发结果绑定发起时的选择；再生成切换输入方式会作废旧结果。源码ZIP比较必须同时选择变更前、变更后两份ZIP，或清除两者后使用文本集合。

rebuild.8：生成代码与质量检查

  • 生成独立Assembler管理新增、完整更新和展示白名单，Service保留权限、上下文、事务及审计；PARTIAL更新保留Present语义。没有新增MapStruct依赖。
  • 纯属性访问器不再自动补重复套话，业务说明和带副作用方法说明保留；已中断线程不再领取Outbox新任务。
  • 接口文档补服务地址与认证定义；契约比较覆盖有效媒体类型，回归报告对空运行、未结束和缺步骤不判通过。列名仅大小写变化不生成新增或删除候选。
  • 源码验证与生成工程测试保留本轮证据；关键检查未执行或全部跳过不能当作测试通过。生产仍需实际目标环境验收。
