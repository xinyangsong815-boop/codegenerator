离线开发助手 Java17 使用说明

适用版本：2.1.1-rebuild.8-java17。查看本轮修复与验证边界。本版来自已恢复的 2.1.0 源码基线，原 2.2.1 源码未取回。

1. Java17 启动

生成器和生成业务工程均采用 Java17、Spring Boot 3.5.16。Windows / Linux 解压运行包后准备对应 CPU 架构的 Java 17；源码构建需完整 JDK 17。Windows 执行 start-windows.cmd，Linux 执行 bash start.sh；浏览器访问 http://127.0.0.1:8790。可用 JAVA_HOME 指定路径。运行包不捆绑 JDK 或 Maven。

java -Xmx512m -Dfile.encoding=UTF-8 -jar offline-dev-assistant-2.1.1-rebuild.8-java17.jar --tool.data-dir=./data

源码包自带经过校验的生成器依赖，可用 bash build.sh 离线编译。生成业务工程的 Maven 测试需要独立依赖仓库或缓存。端口占用时使用 --server.port=8791。生成器端口与业务工程的 8080 端口不同。

2. 升级既有安装

停止旧生成器，备份原 data 目录，再替换程序。旧记录、接口版本、环境和场景通过相同 data 路径继续使用，例如 --tool.data-dir=/原安装路径/data。启动前用 java -version 确认平台。不要同时用两个进程写同一个 data 目录。

Mock 启用配置只在内存中，升级或重启后需要重新生成；历史报告仍能下载。已有生成业务工程不会被本次升级自动改写。需要重新生成时使用“代码更新与冲突”，核对候选结果再合并。本版生成规格支持 schemaVersion 1 / 2，业务回归场景仍用 schemaVersion 1。

3. 生成代码与选择接口形式

“开始使用”选择“生成可启动项目”，进入“需求与代码生成”。载入默认合同 v2 示例，填写模块、字段和操作。默认示例包含新增、部分修改、详情、分页和删除。实际业务仅选择需要的操作。

接口方案可选 REST、BANK_POST 或 LEGACY；REST 使用 POST 新增、PATCH 部分修改、GET 查询、DELETE 删除。BANK_POST 适用于统一 POST 的行内约定。自定义端点可设置方法、路径、业务参数位置与 ID 位置，生成器会拒绝不支持组合，不能随意把请求体挂到 GET 上。选择应与当前项目规范一致。

v2 的 options.wireFormat 可选 STRING_NUMBERS / NATIVE。字符串数字模式将 Long / BigDecimal 作为 JSON 字符串传输，避免前端精度损失，例如 "amount":"123.45"；NATIVE 使用 JSON 数值。按接口文档的字段类型填写回归参数和断言，不能把字符串 ID 与数字 ID 混用。PARTIAL 更新只修改传入字段；未传字段保持原值；空更新拒绝；能否清空字段以 nullable 定义为准。

生成成功后先看校验摘要和文件预览，下载 ZIP。点击“保存生成契约”直接进入接口文档，不必解压后再上传。配置 EXISTING 接入模式生成宿主模块，需要宿主 API、异常、分页等适配，不能当独立 Spring Boot 工程启动。

4. 启动生成的 Spring Boot 业务工程

以下操作在下载的业务工程解压目录执行，不能在生成器自身目录执行。先在专用 MySQL 测试库导入 sql/schema.sql，再按生成的 README 和 application.properties 配置数据库地址、用户和密码。生产基础模式还需实现可信上下文、权限与审计扩展，完成接入检查清单。

生成业务工程需要单独安装 Maven 并准备与该工程匹配的依赖仓库。生成器运行包不包含 Maven 或完整业务依赖仓库。联网环境执行 mvn verify；离线环境指定已经准备好的绝对路径仓库，Windows 可使用 mvn.cmd：

mvn -o -Dmaven.repo.local=/你的完整业务依赖仓库 verify
mvn -o -Dmaven.repo.local=/你的完整业务依赖仓库 package
java -jar target/contract-demo-1.0.0.jar

JAR 实际名称以 target 和 pom.xml 为准。通过环境变量 DB_URL、DB_USER、DB_PASSWORD 配置数据库，具体键以生成 README 为准。生成单元与集成测试使用隔离的 H2 测试配置；测试通过不代表目标 MySQL、Windows、麒麟或行内宿主已经通过验收。业务工程默认访问 http://127.0.0.1:8080。

5. 接口文档与结果身份

“接口文档与版本”支持 Java 源码 ZIP、单文件 OpenAPI 3.0.0–3.0.3 JSON，以及粘贴 JSON。版本名称建议填写“项目 / 模块 / 日期或版本”。扫描 Java 只做源码静态分析，不启动项目；覆盖问题需逐项复核。

接口通过 HTTP 方法与契约路径定位，名称、operationId、标签、描述和源码位置辅助区分。相同路径的 GET 与 POST 是不同接口；相同接口的 200 与 400 是不同响应变体。未填写 summary 时回退 operationId，再回退方法与路径，不猜测业务含义。生成契约已补充中文操作说明、参数位置和更新语义。

6. 离线 Mock 怎么用

选择已保存接口版本，点击“生成用例并启用 Mock”。查看来源名称与契约 ID，按名称、方法、路径或 operationId 搜索。每个接口卡片显示参数、字段、响应状态和校验问题；测试清单可按接口和类型筛选，每页 25 条。

结果含义后续操作
PASS合成响应符合已支持的契约约束可使用可用响应做联调；真实业务仍需回归
INCOMPLETE存在未支持约束、引用或预算限制看覆盖问题，补充人工样例或业务测试
FAIL检查发现响应不符合契约核对 Schema、类型、边界和响应内容
REVIEW_REQUIRED用例需要人工补充业务预期写真实项目错误码、断言后运行回归

复制实际 Mock 基础地址，再拼接接口路径，例如 http://127.0.0.1:8790/mock/配置UUID/contracts/1。默认返回第一个已声明的 2xx；通过请求头 X-Mock-Status: 400 选择已声明且可用的响应。可点“请求此响应”试发。Vue 跨端口联调配置开发代理。Mock 不使用契约 servers，不调用真实后台。

Mock 合成数字字符串、金额精度、日期范围、已登记的正则等；未知正则、复杂组合 Schema 会明确标记 INCOMPLETE，不能删除约束以换取 PASS。Mock 静态返回合成响应，不模拟新增后查询、鉴权、事务、幂等或落库。负例只是检查清单，不能证明服务端拒绝了错误输入。

下载包含 report.json、cases.json、responses.json、requests.http 与说明。requests.http 默认使用占位 UUID，须替换实际启用地址。最多启用 16 个配置，满额时仍保存报告，停用旧配置后再生成。报告会区分请求覆盖与响应校验，一个可用响应不代表请求也已完整合成。

7. 响应样例校验

选择接口版本，再选择带名称、方法和路径的具体接口；填写响应状态、JSON 媒体类型和真实响应。检查结果会标明接口、状态、字段指针和问题。仅校验 JSON（含 +json）媒体；匹配时忽略媒体类型大小写，并按明确类型、类型通配、全通配顺序选择 Schema。其他正文格式会标记检查不完整。修改输入后旧结果清除，避免用旧结论解释新响应。该功能只检查当前样例与已支持约束，原始响应正文不持久保存。

版本比较与可读文档

比较使用“旧请求仍被新服务接受、新响应仍被旧调用方接受”的方向。响应必填字段和响应头的保证取消属于不兼容；HTTP 头名称不区分大小写，query/path 名称区分大小写。空 responses、非法状态码、重复参数／响应头、未知组合约束会保留覆盖问题。HTML／Markdown 同时展示原始 required 字段和响应头必填声明。检查不完整或需复核的报告不能当作无条件通过。

8. 回归到自己的业务项目

启动真实项目并使用专用测试库。默认允许目标 http://127.0.0.1:8080；其他地址在启动生成器时设置白名单：

bash start.sh --tool.regression.allowed-targets=http://127.0.0.1:8080,http://10.0.0.5:8080 --tool.data-dir=./data

在“业务场景回归”填写环境并保存。baseUrl 只包含协议、主机、端口；pathPrefix 是允许访问范围，不会自动加到步骤路径。例：baseUrl=http://127.0.0.1:8080，pathPrefix=/api，步骤应写 /api/contracts/{id}。

从“空白场景”开始，或载入“合同 v2”示例。按真实项目的 OpenAPI / Controller 改方法、完整相对路径、请求字段、HTTP 状态、返回包裹结构和业务断言。不能只换地址而保留停车或员工示例。场景编辑支持新增、编辑、删除、排序；JSON 区可配置更复杂断言。先保存步骤，再校验结构、保存场景。执行使用已保存版本；环境、场景或步骤未保存时会阻止执行。

Token、Session Cookie、CSRF 只在执行区填写，运行后清除；不要写到场景变量或请求体。确认目标是专用测试环境及本次写操作后执行。查看每一步断言和失败原因；PASS 需要业务预期本身正确。清理状态 MANUAL_REQUIRED 表示仍需人工重置测试数据，与断言 PASS 可以同时出现。确认已经实际清理后再点击确认重置，工具不会替你重置数据库。

9. 场景 JSON 示例

场景 schemaVersion 为 1；下面示范“新增 → 用返回 ID 查询”。适用于默认 v2 合同、STRING_NUMBERS 返回，真实项目需更换字段、路径和返回指针。完整新增→查询→修改→查询示例见 examples/regression/contract-v2-flow.json。

{
  "schemaVersion": 1,
  "id": "contract-create-detail",
  "name": "合同新增后详情验证",
  "variables": {"contractNo": {"generator": "runUnique", "prefix": "T-"}},
  "failurePolicy": "STOP",
  "cleanupPolicy": "RESET_TEST_DATABASE",
  "steps": [
    {
      "id": "create", "name": "新增合同",
      "request": {"method": "POST", "path": "/contracts", "body": {"contractNo": {"$var": "contractNo"}, "amount": "123.45", "signDate": "2026-01-01"}},
      "assertions": [{"source": "status", "op": "eq", "expected": 200}, {"source": "body", "pointer": "/code", "op": "eq", "expected": 0}],
      "extract": [{"name": "id", "source": "body", "pointer": "/data", "type": "string", "required": true}]
    },
    {
      "id": "detail", "name": "用新 ID 查询详情",
      "request": {"method": "GET", "path": "/contracts/{id}", "pathVariables": {"id": {"$var": "id"}}},
      "assertions": [{"source": "status", "op": "eq", "expected": 200}, {"source": "body", "pointer": "/data/contractNo", "op": "eq", "expected": {"$var": "contractNo"}}]
    }
  ]
}

JSON Pointer /data 读取返回 JSON 的 data 字段本身；如果响应是 {"data":{"id":1}}，则用 /data/id 提取 id。$var 必须引用前面已定义或提取的变量，不能嵌在字符串里写 ${id}。query 中基本值数组以同名参数重复传输，例如 {"id":["1","2"]} → ?id=1&id=2；暂不支持 query 嵌套对象或空数组。不同错误状态通过真实项目场景分别验证。

10. 离线维护与交付目录

两平台分别提供运行包和源码包。运行包包含助手 JAR 与启动脚本；源码包包含 Java 源码、模板、静态页面、构建脚本及经过校验的生成器依赖。依赖位置以本包 README 为准，不要使用其他历史包的 sources 或 tools/maven-repository 路径。

构建生成器：在源码根目录执行 bash build.sh，Windows 使用 build.ps1；产物位于 dist。执行验证脚本需按 README 准备测试环境。生成业务工程的编译、Maven 依赖及目标数据库验收另行完成。保留升级前备份及完整 data 目录。
