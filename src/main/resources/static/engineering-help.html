本页说明 EXISTING 接入模式。启动、依赖与完整流程见 当前使用说明。

接入现有工程

EXISTING 模式输出可合入宿主工程的业务模块；STANDALONE 输出独立工程。本包 Java 8 / Spring Boot 2.7.18。Java 8 与 Java 17 分别构建、同步维护，宿主需要自行确认版本兼容。

使用步骤

  1. 停止旧工具，备份工具数据目录，替换对应平台 JAR。使用新版本内置模板；若启动时指定 tool.template-dir，先更新自定义模板并适配新增模型字段。
  2. 打开“需求与代码生成 → 工程接入”，选择“接入现有工程”。填写模块独立包名和已有公共组件信息。
  3. 先“载入工程适配示例”查看完整规格。com.example.host 是演示类名，必须换成工程中真实类名。
  4. 核对接口方法、路径、参数位置和字段，生成并下载模块包。
  5. 按模块 README 合入宿主工程，完成离线编译、宿主测试和现场接入验收。

同一工程的公共组件配置可“导出工程适配配置”，在其他业务模块“导入工程适配配置”。该配置仅覆盖 integration，不覆盖业务字段和接口。输入限32KB；生成时服务端仍会校验。完整规格导出也保留 integration。

支持的公共组件签名

返回类必须是泛型，例如 ApiResult；静态成功工厂接收 T 并返回兼容的 ApiResult，如 ApiResult.ok(data)。修改、删除传 null。

分页类是 HostPage。支持两种形式：静态泛型工厂 HostPage.of(List, long)，或公开构造器 new HostPage(List, long)。参数顺序固定为记录列表、总数；其他形式先在行内项目增加一个适配工厂。

业务异常必须继承 RuntimeException。支持静态工厂 HostException.missing(String)，或公开构造器 new HostException(String)。notFoundMethod 未指定时默认 notFound；显式空字符串选择构造器。记录不存在的实际 HTTP 状态和错误协议由宿主全局异常处理器决定。

公共类名必须为合法完整类名，位于生成模块包名之外；本版不支持内部类、非泛型返回类、多参工厂、反射、任意 Java 表达式或代码片段。

示例配置

{
  "integration": {
    "mode": "EXISTING",
    "resultClass": "com.example.host.ApiResult",
    "successMethod": "ok",
    "exceptionClass": "com.example.host.HostException",
    "notFoundMethod": "missing",
    "pageClass": "com.example.host.HostPage",
    "pageFactoryMethod": "of",
    "dataProperty": "body",
    "codeProperty": "retCode",
    "codeType": "STRING",
    "successCode": "0000",
    "messageProperty": "retMsg",
    "recordsProperty": "rows",
    "totalProperty": "totalCount"
  }
}

示例是完整生成规格中的 integration 部分；完整可导入示例为 examples/engineering-spec.json。返回形状约定为 retCode/retMsg/body，分页 body.rows/body.totalCount。

codeType 支持 STRING / INTEGER，successCode 始终在规格中填字符串文本，例如 "0000" 或 "0"。整数限制为 Long 范围。codeProperty 或 messageProperty 显式填空串，可不声明该属性；dataProperty 必须非空。省略字段时分别默认 code/message/data、INTEGER、"0"。

未指定 pageClass 时使用本模块 PageResult，字段固定 records/total，不允许额外配置外部分页工厂或字段映射。指定分页类后，pageFactoryMethod 省略或空串都选择构造器。

响应字段映射只用于生成声明的 OpenAPI 契约，不改变外部类的序列化行为。外部类的额外属性允许存在；生成器不读取行内 JAR，不验证静态工厂的实际签名或成功码。OpenAPI 标记 hostVerification=REQUIRED；错误响应采用 default 声明，不预设宿主的 404 或其他错误协议。

合入时需核对

  • 宿主 Spring 与 MyBatis 版本应兼容平台基线；保留宿主 BOM，依赖由宿主管理。
  • 业务包必须在组件扫描和 Mapper 扫描范围内；Mapper XML 必须被已配置的 mapper-locations 加载。
  • Service 方法校验依赖 Spring 的 @Validated 代理；直接 new ServiceImpl 不会执行完整约束。
  • 默认 MODULE 策略只约束本实体生成的请求 DTO，不改变宿主其他 DTO 的 JSON 行为；配置类和 Bean 名包含实体及包名。宿主统一治理时可选择 HOST 并自行验收 JSON 行为。模块不更改端口、数据源、事务、静态资源或全局错误策略。
  • 数据结构 SQL 仅作参考，使用宿主已有迁移流程。不要对已有业务表直接执行 CREATE TABLE。
  • 前端 api.js 注入宿主 HTTP 客户端，返回值保持宿主客户端的结果；响应拦截器是否解包须与页面约定一致。
  • 用真实响应核对成功码、字段名、null 序列化、空分页、无数据操作及错误响应。integration/verification-checklist.json 初始均为 NOT_VERIFIED。

生成器仍提供单表 CRUD。生产选项可生成权限扩展点、审计、乐观锁、幂等与 Outbox 结构；可信身份、机构／对象权限、持久化策略和业务审批仍须接入宿主机制并验收。支持这些公共类型签名不等于已经接入你的行内工程。

重新生成

保留 generation-spec.json 和 generation-manifest.json，在工具“代码更新与冲突”中提交新规格与当前模块 ZIP，下载候选包和冲突报告，人工合并。模式切换也可能产生新增或建议删除项，不会直接覆盖宿主文件。
